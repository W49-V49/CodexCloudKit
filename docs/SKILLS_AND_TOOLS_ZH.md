# 共享技能、工具与 MCP

核心 `setup` 准备五项共享技能：按需记忆、增量索引、目标监督、测试修复和 Agent 编排。`attach` 将这些技能作为引用接入业务仓库，保留项目自有技能和规则。

## 规则读取

项目原 `AGENTS.md` 与生成的 `AGENTS.cloudkit.md` 一起读取。自动发现技能与显式读取技能文件是不同路径；在客户端没有自动发现时，直接读取本轮需要的技能正文。

MCP 配置、技能文件和角色模板描述了接入方式。实际服务仍要启动并完成协议调用；当前聊天窗口是否热加载取决于宿主。

## 项目工具

语言工具、浏览器、数据库、二进制分析器与模型服务由项目需求决定。使用固定版本和可核对的包来源，在共享运行目录或任务自己的环境中安装。业务依赖继续使用该项目的锁，不把两个项目的依赖目录互换。

## 启动项目记忆 MCP

准备 memory 配置后，可以通过 stdio 启动包内服务：

```bash
cloudkit mcp --runtime-root /workspace/external-tools/codexcloudkit \
  --state-dir /workspace/persistent-memory/cloudkit \
  --project-root /workspace/business-project
```

客户端以这个命令和参数启动服务，再完成 initialize、工具发现和项目绑定调用。服务根据 GitHub origin 和分支识别项目；显式提供的 `--project-id`、`--branch` 必须与真实项目一致。检索入口先读取项目短目标与活动断点，项目需准备对应的目标和状态文件。

## MCP 验证

每个服务分别验证启动、初始化、工具发现、真实只读调用、项目身份和需要的写操作。切换项目后重新启动绑定进程，确认它服务于当前根目录和分支。

平台网络密钥可能通过代理替换占位值；需要本地真实值的 stdio 服务必须匹配相应凭据交付方式。把配置列出来不等于已完成模型、MCP 或外部账号认证。

## Hooks 与 Agent

根据宿主实际支持的事件接入 hook。持久任务触发、模型进程和 Agent 协作分别有自己的运行生命周期。按任务使用真实子 Agent，记录父子关系与交接；安装角色文件不代表相同数量的 worker 已经启动。
