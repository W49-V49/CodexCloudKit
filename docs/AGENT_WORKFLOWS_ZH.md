# 多 Agent 与目标执行流程

每次任务先读取短目标、验收条件和活动断点。将可以独立完成的工作交给真实 Agent：例如后端实现、界面实现、测试和独立复核。需要进一步分解时，由负责人派生副 Agent 或叶子任务。

## 交接记录

每份交接至少包含目标、项目身份、源版本、文件所有权、输入来源、验收要求、日志位置和下一动作。同一个共享文件由一个写入者负责；其他 Agent 提供审阅结果或独立文件。

角色目录和提示文件本身不会启动模型。统计实际启动的 Agent ID、父子关系及结果，避免把安装的角色数量当作真实并发。

## 从目标到 DONE

1. 估算时长，保存目标、验收版本、后端配置和下一动作。
2. 恢复状态，按需召回相关事实与代码位置。
3. 探测实际后端，派发适合的独立工作。
4. 收集修改并运行独立验收命令。
5. 失败时记录失败类型、日志摘要和输出变化，继续修复。
6. 同类错误两次或连续三次无进展时，熔断当前路线，切换适用的独立后端。
7. 验收通过后归档证据、精选写回并标记 DONE；停止该目标的重复派发。

预计超过一小时的任务，应先配置即时下一步触发和小时巡检。巡检恢复过期租约、未派发事件和中断步骤。队列启动时间由运行平台决定，立即派发不等于物理零秒启动。

## 验收证据

分别记录命令执行、模型调用、实际 Agent 派生和业务功能验收。一个合成工作进程可以验证调度器的失败、修复、恢复与去重，但不能替代真实 Codex 模型请求和项目验收。
